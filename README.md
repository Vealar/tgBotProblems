# Telegram-бот для базы математических задач

Небольшой индивидуальный pet-проект — Telegram-бот для поиска и хранения математических задач.

Идея проекта — перенести основные сценарии работы с базой задач в Telegram: пользователь может искать задачи по темам и сложности, просматривать условия и решения и вести собственный список решённых задач.

**Исходный код:**  
https://github.com/Vealar/tgBotProblems

## Возможности

Бот позволяет:

- зарегистрироваться в системе;
- просматривать доступные математические задачи;
- искать задачи по одной или нескольким темам;
- фильтровать задачи по уровню сложности;
- одновременно использовать фильтр по темам и сложности;
- получать конкретную задачу по идентификатору;
- просматривать решение задачи;
- отмечать задачи как решённые;
- просматривать историю решённых задач;
- отменять отметку о решении;
- полностью очищать собственную историю.

Также реализована отдельная административная часть для управления содержимым базы.

Администратор может:

- добавлять и удалять задачи;
- создавать и удалять темы;
- изменять условие задачи;
- изменять решение;
- менять уровень сложности;
- привязывать к задаче одну или несколько тем.

## Технологии

Основной стек проекта:

- **Python**;
- **aiogram**;
- **PostgreSQL**;
- **SQLAlchemy**.

Для обработки Telegram-сообщений и пользовательских сценариев используются `Dispatcher` и отдельные `Router`.

Маршрутизация разделена по функциональным областям:

- регистрация;
- пользовательские операции;
- поиск;
- административные команды.

Для сценариев, в которых пользователь последовательно задаёт несколько параметров поиска, используется **FSM aiogram**.

## Архитектура

Проект разделён на Telegram-слой и слой работы с данными.

### Telegram-слой

Содержит обработчики:

- регистрации;
- пользовательских команд;
- поиска;
- административных функций.

Обработчики отвечают за взаимодействие с пользователем и передают выполнение операций соответствующим сервисам.

### Работа с данными

Для доступа к данным используются:

- модели SQLAlchemy;
- DTO;
- слой подключения к базе данных;
- сервисы пользовательских операций;
- сервисы административных операций.

Основные сущности базы данных:

- пользователь;
- задача;
- тема.

## Модель данных

Между задачами и темами используется связь **многие-ко-многим**.

Одна задача может относиться сразу к нескольким темам, а одна тема — содержать множество задач.

Аналогично устроена связь между пользователями и решёнными задачами: каждый пользователь может решить несколько задач, при этом одна и та же задача может быть отмечена как решённая множеством пользователей.

За счёт этого история прогресса хранится отдельно для каждого пользователя.

## Поиск задач

Основная часть пользовательской функциональности связана с поиском.

Пользователь может:

- вывести все задачи;
- искать по одной теме;
- искать сразу по нескольким темам;
- искать по уровню сложности;
- комбинировать сложность и темы;
- получить задачу по её идентификатору.

Для многошаговых сценариев используется FSM.

Например, бот может последовательно запросить у пользователя темы, затем уровень сложности и после этого выполнить поиск по собранным параметрам.

## Учёт решённых задач

Для каждого пользователя хранится собственный набор решённых задач.

Пользователь может:

- отметить задачу как решённую;
- убрать отметку;
- посмотреть список уже решённых задач;
- полностью очистить историю.

Данные о прогрессе хранятся в PostgreSQL и не зависят от текущей Telegram-сессии.

## Административная часть

Для работы с содержимым базы не требуется напрямую обращаться к PostgreSQL.

Через административные команды можно:

- создавать новые задачи;
- удалять задачи;
- создавать и удалять темы;
- редактировать условие;
- изменять решение;
- изменять сложность;
- назначать и изменять темы задачи.

Таким образом, основное содержимое базы можно поддерживать непосредственно через интерфейс Telegram-бота.

## Результат

В результате был реализован работающий Telegram-бот с реляционной моделью данных и основными сценариями работы с базой математических задач.

Проект включает:

- регистрацию пользователей;
- хранение задач и решений;
- классификацию по темам и сложности;
- поиск и фильтрацию;
- индивидуальную историю решённых задач;
- административное управление базой.

Основная идея проекта — использовать Telegram как готовый пользовательский интерфейс для небольшой системы хранения и поиска задач вместо разработки отдельного веб-приложения.

## Возможности дальнейшего развития

В дальнейшем проект можно расширить за счёт:

- отдельного веб-интерфейса для администрирования;
- массового импорта задач;
- загрузки задач из внешних источников;
- более сложного поиска;
- рекомендаций задач на основе истории пользователя;
- статистики прогресса по темам и уровням сложности.
